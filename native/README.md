# StaffList for iPad and iPhone

The iPad / iPhone app is a thin native shell (Capacitor) around the live web app. It loads
https://stafflist.app, so every web update reaches the app without a new App Store
build. The shell adds one thing a browser can't do:

**TV output that shows only the Now Showing slide.** When the user turns on Screen Mirroring to
an Apple TV / AirPlay TV, the app gives the TV its own screen with the presentation page
(`/present/<set>?tv=1`) while the iPad / iPhone keeps the controller. In Safari, mirroring
copies the whole screen instead.

| Piece | Where |
|---|---|
| Xcode project | `ios/App/App.xcodeproj` (Capacitor 8, Swift Package Manager — no CocoaPods) |
| TV scene | `ios/App/App/TVSceneDelegate.swift` (routed from `AppDelegate.swift`, declared in `Info.plist`) |
| TV plugin (Swift) | `ios/App/App/ExternalDisplayPlugin.swift` |
| Plugin registration | `ios/App/App/MainViewController.swift` (used by `SceneDelegate.swift` and `Main.storyboard`) |
| JavaScript bridge | `src/lib/externalDisplay.js` |
| TV page | `src/pages/PresentMode.jsx` with `?tv=1` (no controls, follows the controller) |
| Controller + connect steps | `src/pages/Controller.jsx` |
| App config | `capacitor.config.json` (bundle id `app.stafflist`) |

## Opening the project on a Mac

Needs: macOS, Xcode 26 or later, Node 20+ (`brew install node`), and an Apple Developer
account ($99/year) to run on a device and publish.

```bash
git clone https://github.com/Pyrotek-90/PresentGO.git && cd PresentGO
npm install
npm run ios          # builds, syncs Capacitor into ios/, and opens Xcode
```

The first time Xcode opens it downloads the Capacitor Swift packages (watch the progress in the
left sidebar). Then:

1. **Signing.** Click the blue *App* project → *App* target → *Signing & Capabilities* → tick
   *Automatically manage signing* and choose your Team.
2. **Run** on an iPad or iPhone (plug it in, choose it at the top of the Xcode window, ▶).
   The simulator has no AirPlay; use *I/O → External Displays* in the simulator to try the TV
   screen.

After pulling new changes, or after changing `capacitor.config.json`, run `npm run ios:sync`.
`ios/App/App/public`, `capacitor.config.json` inside `ios/` and `capacitor-cordova-ios-plugins`
are generated by the sync and are not committed.

### Scene life cycle

Apps built with the iOS 27 SDK must use the UIScene life cycle or they fail to launch, so the
app uses scenes. The TV arrives as its own non-interactive scene: `AppDelegate` sends any
non-application scene to `TVSceneDelegate`, which hands it to `ExternalDisplayPlugin`. With no
window in that scene the TV keeps mirroring; the plugin adds a window when presenting starts and
removes it at End.

## How presenting works in the app

1. Open a set → **Present**. The connect screen shows app-specific steps and a live
   "TV connected — <name>" status.
2. Control Center → **Screen Mirroring** → choose the TV. The TV shows only the slide.
3. Run the service from the controller. Control messages go to the TV page directly through
   the app (no internet needed) and also over Supabase Realtime.
4. **End** removes the TV screen; the TV goes back to mirroring.

StaffList must stay in the foreground while presenting: if the user switches apps, iOS returns
the TV to plain mirroring until StaffList is opened again.

## Before submitting to the App Store

- **Google sign-in:** Google blocks its sign-in page inside embedded web views, so "Sign in with
  Google" will fail in the app. Email / password and Sign in with Apple work. Fix before release
  with a native sign-in plugin (e.g. `@capacitor-community/apple-sign-in`, a native Google
  sign-in plugin) or by opening the sign-in in Safari (`@capacitor/browser`) and returning via a
  deep link.
- **App Review guideline 4.2 (minimum functionality):** apps that are only a website in a wrapper
  can be rejected. The second-screen TV output and native sign-in help show it is an app; mention the TV output in the review notes.
- **Upgrades / Stripe (guideline 3.1.1):** subscriptions bought inside an iOS app generally have
  to use Apple's in-app purchase. Until RevenueCat in-app purchase is built, hide the Upgrade /
  Stripe Checkout buttons when `isNativeApp()` is true (existing subscribers keep their plan).
  Apple's rules on linking out to web checkout have been changing — check the current guideline
  before relying on a link.
- **Account deletion (guideline 5.1.1(v)):** already in Settings (`DeleteAccount.jsx`).
- **Reviewer login:** give App Review a demo account in App Store Connect, since the app opens
  to sign-in.
- Icons and launch screen: see below.

## App icon and launch screen

The artwork is in `assets/`:

| File | What it is |
|---|---|
| `assets/icon-only.png` | 1024×1024 app icon (square, no transparency; iOS rounds the corners) |
| `assets/splash.png`, `assets/splash-dark.png` | 2732×2732 launch screen: the logo, "StaffList" and "To the Chief Musician" on the app's dark background, kept to the middle so it fits every iPad and iPhone shape |

The generated icon and launch-screen sizes are already in `ios/App/App/Assets.xcassets`. If the
artwork changes, replace the files in `assets/` and run:

```bash
npm run ios:assets
npm run ios:sync
```

The launch screen stays up until StaffList has drawn its first screen, then fades out (at most
4 seconds, set in `capacitor.config.json`).
